# MuhammaraJS Changes To PDFWriter

This directory is vendored from
[PDF-Writer v4.9.1](https://github.com/galkahana/PDF-Writer/tree/v4.9.1/PDFWriter).
MuhammaraJS changes the files below. Reapply these changes when updating
PDFWriter, and drop any that the new upstream version already contains.

To list every difference, compare this directory with the upstream tag:

```sh
git clone --depth 1 --branch v4.9.1 https://github.com/galkahana/PDF-Writer.git
diff -ru --strip-trailing-cr PDF-Writer/PDFWriter packages/native-with-source/src/deps/PDFWriter
```

## Thread Safety

`recryptAsync()` runs `PDFWriter::RecryptPDF` on a libuv pool thread while
writers keep running on the JavaScript thread. These changes are marked with
`MuhammaraJS:` comments; the reasons and the audit of the remaining global state
are in
[Security And Vendored Dependencies](../../../../native/docs/security.md#thread-safety-patches-in-pdfwriter).

| File                     | Change                                                        |
| ------------------------ | ------------------------------------------------------------- |
| `Trace.cpp`              | `Trace::DefaultTrace()` returns a `static thread_local` trace |
| `SafeBufferMacrosDefs.h` | `SAFE_LOCAL_TIME` uses `localtime_r()` on POSIX               |
| `PDFDate.cpp`            | `SetToCurrentTime()` uses `gmtime_r()` / `gmtime_s()`         |
| `PDFDate.h`, `PDFDate.cpp`, `Log.cpp` | `PDFDate::SetThreadTimeZone()` fixes a thread's time zone; `SetToCurrentTime()` and log timestamps then use it instead of reading `TZ` |

## Robustness Fixes

| File                                           | Change                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DictionaryContext.h`, `DictionaryContext.cpp` | `Discard()` releases a dictionary without writing its closing `>>`.                                                                                                                                                                                                                                           |
| `ObjectsContext.h`, `ObjectsContext.cpp`       | `HasOpenDictionaries()` reports dictionaries left open, and `Cleanup()` discards them instead of writing to an output stream that may already be closed. The destructor releases them too, so a writer destroyed without `Cleanup()` after a failed copy no longer leaks them. |
| `PDFModifiedPage.cpp`                          | Editing a page tolerates malformed entries: a failed copying context or page dictionary ends the edit with an error instead of leaking, a non-array `Annots` is dropped, `Contents` that do not resolve or are not references are dropped, and non-dictionary `Resources` are replaced.                       |
| `UsedFontsRepository.cpp`                      | A font that failed to load, cached as `NULL`, no longer fails `WriteUsedFontsDefinitions()` and with it the whole document.                                                                                                                                                                                   |
| `PDFPageMergingHelper.cpp`                     | `MergePageContent()` deletes the copying context it creates.                                                                                                                                                                                                                                                  |
| `PDFParser.cpp`                                | `ParseExistingInDirectStreamObject()` rejects an object stream whose `/N` is negative or larger than the xref table, like the `/Count` check in `ParsePagesObjectIDs()`, instead of terminating the process when the header allocation fails ([#917](https://github.com/julianhille/MuhammaraJS/issues/917)). |
| `PDFParser.cpp` | `ParseExistingInDirectStreamObject()` points its object parser back at the file before it deletes the object stream's reader to open the stream again, which it does when reading the header overshot the object. Re-opening resolves an indirect `/Length` through that parser, which read the deleted reader: a use-after-free on object streams whose header ends right at their first object, as Cairo writes them ([#959](https://github.com/julianhille/MuhammaraJS/issues/959)). |
| `PDFWriter.cpp`                                | The stream overload of `RecryptPDF()` ends with `EndPDFForStream()` and returns its status, so a failed write is reported.                                                                                                                                                                                    |
| `PDFUsedFont.cpp`                              | `CalculateTextDimensions()` skips a glyph that FreeType cannot load instead of reading the uninitialized `FT_Glyph` and calling through its class pointer.                                                                                                                                                    |
| `PDFStream.cpp`, `OutputFlateEncodeStream.h`, `OutputFlateEncodeStream.cpp` | The destructor detaches the flate encoder with the new `Detach()`, which drops the unfinished encoding without writing its tail, so a stream deleted without `FinalizeStreamWrite()`, such as the content of a form whose page failed to copy, no longer deletes the document's output stream, and deletes its encryption stream. |
| `InputDCTDecodeStream.h`, `InputDCTDecodeStream.cpp` | libjpeg errors `longjmp` from `error_exit` to a `setjmp` around each libjpeg call, as libjpeg's example does, instead of throwing a C++ exception through libjpeg's C frames, which aborted the process where those frames have no unwind tables (riscv64) and escaped the Wasm module. `Read()` ends decoding after an error in the header or the scan lines instead of reporting pending data it cannot return or calling libjpeg again. |
| `CFFFileInput.cpp` | `GetLocalSubr()` returns no subroutine when the font's private dictionary has no `Subrs`, instead of reading through a null pointer. `ReadLocalSubrsForPrivateDict()` releases subrs it failed to read and leaves the dictionary without subrs, instead of leaking them and reading the map's end iterator. An empty Name INDEX or FDArray, a Top DICT INDEX whose count differs from the font count, and an out-of-range font index fail, in both `ReadTopDictIndex()` overloads, and a font that is not found is reported as a failure. An empty name in the Name INDEX is no longer read past its end. |
| `PDFParserTokenizer.h`, `PDFParserTokenizer.cpp`, `PDFObjectParser.h`, `PDFObjectParser.cpp`, `PDFParser.cpp` | `SetReadLimit()` bounds the bytes a parser reads from its stream, `ConsumeReadBudget()` charges bytes read past it (an inline image skipped through an external read), and `ReachedReadLimit()` reports hitting either. `SetMaxTokenSize()` fails a longer token and stops tokenizing until `ResetReadState()`; the object parsers of `StartReadingObjectsFromStream(s)()` set 32 MiB, as decoded content expands far beyond the input. |
| `InputStreamSkipperStream.h`, `InputStreamSkipperStream.cpp`, `PDFParser.cpp` | `EnableReadAhead()` reads the source in blocks; the object parsers of `StartReadingObjectsFromStream(s)()` use it, so a byte no longer costs a decode-filter call.                                                                                                                                            |
| `SimpleStringTokenizer.h`, `SimpleStringTokenizer.cpp`, `PDFDocumentHandler.cpp` | `SetMaxTokenSize()` keeps at most that many bytes of a token and reads past the rest, so positions and later tokens are unchanged; `ScanStreamForResourcesTokens()` sets 32 MiB, so one token of decoded content no longer grows a string until allocation fails when a page is merged. |
| `InputBufferedStream.cpp`                      | `NotEnded()` checks its buffer before the source stream.                                                                                                                                                                                                                                                      |
| `PDFDocumentHandler.cpp`                       | `ScanStreamForResourcesTokens()` reads the decoded content through a read-ahead buffer, so merging a page no longer costs a decode-filter call per byte.                                                                                                                                                      |
| `PDFDocumentHandler.cpp` | `WriteStreamObject()` closes the stream dictionary it started when copying the dictionary fails. The copy still leaves its object unfinished, so the document cannot end: the failure aborts the copy, it does not recover from it. |
| `PDFDocumentHandler.cpp` | `CreatePDFFormXObjectForPage()` ends the form it started when the page content fails to copy, so the output stays writable; the form is written with the content copied so far. `/ProcSet` entries that are not names are skipped when merging a page into a page or a form, instead of being read as `PDFName`. |
| `PDFObjectCast.h`, `AbstractWrittenFont.cpp`, `DecryptionHelper.cpp`, `DocumentContext.cpp`, `PDFDocumentHandler.cpp`, `UsedFontsRepository.cpp`, `WrittenFontCFF.cpp` | `PDFObjectCastPtr::Borrow()` takes a reference only when the type matches. The 20 sites that cast an array item or dictionary value, which they do not own, use it instead of assignment, which released the borrowed object on a type mismatch. |
| `DecryptionHelper.cpp` | A crypt filter without `/CFM`, which defaults to `None`, is skipped instead of reading its name through a null pointer. |
| `DecryptionHelper.cpp` | `GetCryptForStream()` treats a `Crypt` filter whose `/DecodeParms` has no `/Name` as `Identity`, as `PDFParser::CreateFilterForStream()` does, instead of reading the name through a null pointer when an encrypted document's stream is parsed (GHSA-q3f9-hvrq-7wwh). |
| `UnicodeString.cpp` | `FromUTF16BE()` and `FromUTF16LE()` stop at `i + 1 < inLength` instead of `i < inLength-1`, which wrapped around for an empty string. A text string that is only the UTF-16BE byte order mark (`<FEFF>`) now decodes to `""` instead of reading heap memory past its end (GHSA-f2qr-8r8j-mm94). |
| `PDFParser.cpp` | `ParsePagesIDs()` fails a `null` `/Kids` entry past the page tree's `/Count`, as it already did for a page, instead of writing past `mPagesObjectIDs`, which is sized from `/Count` (GHSA-8j62-hp3j-vp33). |
| `InputPredictorTIFFSubStream.cpp` | `Read()` and `NotEnded()` return `0` and `false` when `Assign()` rejected the predictor parameters and left `mReadColorsCount` `0`, as `InputPredictorPNGOptimumStream` already does, instead of reading zero-byte rows forever when `/Columns` times `/Colors` overflows (GHSA-5pp7-hx79-5mm2). |
| `RC4.cpp` | `RC4::Init()` skips the key schedule for an empty key instead of dividing by zero. The parser decrypted a string with the empty key when an xref offset or an object stream header pointed at it in an RC4-encrypted document, as no object key is set while it reads an object header, and so did a stream with two `/Crypt` filters, an unused `AESV3` one, whose file key is empty in a `/V 4` file, before an RC4 one, as both got the first one's object key (GHSA-6qj6-hc67-3vfp). |
| `EncryptionHelper.cpp` | `CreateEncryptionStream()` returns `NULL`, so the stream is written unencrypted, when no stream crypt filter was set up, as `EncryptString()` already does for strings, instead of reading through a null pointer when a document whose `/StmF` is `Identity`, `/CFM /None` or otherwise not usable is modified (GHSA-wj5h-wf8p-8vhv). |
| `DocumentContext.cpp`, `EncryptionHelper.cpp` | `ReadState()` hands the encryption helper to the objects context, as the other setup paths do, so what a writer from `createWriterToContinue()` adds to an encrypted document is encrypted instead of written in plaintext. The state keeps the stream and the string crypt filter as `StreamsEncryption` and `StringsEncryption` instead of only one named `StdCF`, so a continued modification of a document with other or separate crypt filters encrypts with them; an older state's `DefaultEncryption` is still read for both. Reading the state rejects an `AESV2` key shorter than 88 bits, whose object keys are not the 128 bits AES needs, or an `AESV3` key that is not the 256 bits the specification requires (GHSA-fvpv-4wx7-85f6). |
| `DecryptionHelper.cpp`, `InputAESDecodeStream.cpp`, `OutputAESEncodeStream.cpp`, `XCryptionCommon2_0.cpp` | `InputAESDecodeStream` and `OutputAESEncodeStream` check the AES key setup, which rejects a key that is not 16, 24 or 32 bytes: the decoder then drops its source, reads nothing and ends, and the encoder fails writing. They ignored the failure and decrypted and encrypted with an uninitialised AES context, and reading such a stream never ended. A short crypt filter key reached them, and so did another crypt filter's key: two `/Crypt` filters on a stream were both decrypted with the first one's object key, and one `/Crypt` without `/DecodeParms` was keyed by `/StmF` but decrypted by a crypt filter named `Identity`. `decryptKeyCBCZeroIV()` returns no key unless `/UE` or `/OE` is 32 bytes, as AES-CBC rejects a length that is not a multiple of 16 and left the output uninitialised: a 24-byte `/UE` gave an uninitialised 24-byte file key, which the key setup accepts. `Setup()` derives an `AESV2` crypt filter's key with 128 bits when its `/Length` is under 88 bits, as a shorter key gave object keys, of the key length plus 5 bytes, that AES rejects. It fails when the crypt filter of `/StmF` or `/StrF` has an `AESV2` file key still shorter than 88 bits, as revision 2 derives a 5-byte key whatever the `/Length`, or an `AESV3` file key, decrypted from `/UE` or `/OE`, that is not the 256 bits the specification requires, so recrypting or modifying such a file throws instead of producing empty output; an unused crypt filter does not fail it (GHSA-7rr8-wph2-845v). |
| `InputAESDecodeStream.cpp`, `InputAscii85DecodeStream.cpp`, `InputLZWDecodeStream.cpp`, `InputRC4XcodeStream.cpp` | `InputAESDecodeStream::Read()` drops its source and ends when the stream is shorter than the IV and one block, instead of returning nothing once and decrypting the never-filled block buffer on the next read, which returned up to 16 bytes of uninitialised memory, heap addresses included. `InputRC4XcodeStream::Read()` and `InputAscii85DecodeStream::ReadNextBuffer()` stop when their source returns no byte, as such an AES stream does, instead of decoding their uninitialised read byte: RC4 returned it as a stray byte of stack memory. `InputLZWDecodeStream::ProcessNextCode()` fails a first code after a clear-table code that is the next table entry, which repeats the first byte of a previous sequence that does not exist, instead of returning that never-written byte (GHSA-mvmf-5vvf-74m7). |
| `CharStringType2Interpreter.cpp` | `InterpretDiv()` fails the charstring on an integer division by zero or of `LONG_MIN` by `-1`, as `CharStringType1Interpreter::InterpretDiv()` already does, instead of raising SIGFPE natively or trapping in Wasm when a crafted CFF font is subset at `end()` (GHSA-32r6-f4hm-ccc4). |
| `CharStringType2Interpreter.cpp` | `InterpretRoll()` fails the charstring when fewer than two operands, or fewer items than it rolls, are on the stack, or the item count is negative or a real that does not fit a `long`. A shift that does not fit a `long` rolls by zero, and the shift is reduced to the remainder of the item count. A crafted CFF font subset at `end()` no longer reads and frees past an empty operand list, which crashed natively, or rotates as often as the shift amount (GHSA-fm69-f3cr-v22g). |
| `PDFPageInput.cpp`, `DocumentContext.cpp` | `AssertPageObjectValid()` returns after tracing a `NULL` page object instead of reading `/Type` through it, which `ParsePage()` returns for an index past the last page or a `null` `/Kids` entry. `GetImageDimensions()` measures such a page as 0 by 0, like an unreadable image, instead of the A4 default of `GetMediaBox()` (GHSA-r4mx-qx34-mrx3). |
| `PDFParser.cpp` | `ParsePagesObjectIDs()` zero-fills `mPagesObjectIDs`, so the pages of a `/Count` larger than the leaves under `/Kids` are null pages, like a `null` `/Kids` entry, instead of uninitialised heap values that `GetPageObjectID()` returned and `ParsePage()` parsed. `ParsePage()` checks that the page has a `/Type` name before reading it (GHSA-7pgh-4m9g-9wrj). |
| `InputPredictorTIFFSubStream.cpp` | `Read()` reads each row as the whole bytes `Assign()` sizes it to, rounding `/Columns` times `/Colors` times `/BitsPerComponent` bits up instead of down, and `Assign()` sizes the colors array to those whole bytes, so it holds the padding colors of a row that does not end on a byte. A row under a byte read no byte, so the stream never ended, also inside one read of a filter after it, and with 1, 2 or 4 bits per component a row that does not end on a byte took the colors of its last byte from past the end of `mReadColors`, which returned heap memory (GHSA-rw6g-24h2-52ch). |
| `InputPredictorPNGOptimumStream.cpp` | `DecodeNextByte()` passes a row whose filter type is none of the five PNG types through unchanged, as type 0 and xpdf do, instead of leaving the decoded bytes unwritten, which returned the caller's read buffer: heap memory on native and leftover linear memory, data of other documents included, on Wasm (GHSA-7gx7-f7mg-m8w6). |
| `InputPredictorPNGOptimumStream.cpp`, `InputPredictorTIFFSubStream.cpp`, `PDFParser.cpp` | `Assign()` rejects a row over 1 MiB, so the stream reads nothing, instead of allocating whatever `/Columns` asks for, which aborted the native process with `std::bad_alloc` or exhausted its memory, and aborted Wasm. `Read()` allocates the row buffers on its first call instead of `Assign()`, so a filter chain being set up holds none of them, also while a `/DecodeParms` entry in an object stream sets up that stream's chain; `Read()` and `NotEnded()` tell rejected parameters by `mBufferSize` or `mReadColorsCount` `0`. `CreateInputStreamReader()` fails a `/Filter` array with more than 8 entries, as each stage holds its own buffers. The PNG `Assign()` takes ownership of its source stream first, as the TIFF one does, so rejected parameters no longer leak it (GHSA-rw3m-455p-xvhr). |
| `DocumentContext.cpp` | `WriteCombinedPageTree()` fails when the original page tree root does not parse or is not a dictionary instead of reading through a null pointer, which crashed `end()` after adding a page to a PDF modified without its user password whose page tree root sits in an object stream it cannot decrypt (GHSA-6rw3-h5pc-hc2x). |
| `InputLimitedStream.cpp` | `Read()` returns `0` when nothing is left to read instead of casting a negative limit, left by a negative `/Length`, to an unbounded read size, which copied the rest of the file into the one-byte stack buffer of a filter that reads its source a byte at a time, such as `LZWDecode`, and crashed native and Wasm (GHSA-7q35-5h53-wm34). |
| `InputDCTDecodeStream.cpp` | `StartRead()` fails a progressive or multi-scan JPEG whose coefficients would take more than 256 MiB, so the stream reads nothing. libjpeg keeps them for the whole image, sizes them from the frame header alone and allocated whatever it asked for, which exhausted native memory and aborted Wasm. Its `max_memory_to_use` would not bound them, as it sums their sizes in a `long`, which wraps where `long` is 32-bit (GHSA-h459-gv45-xfgv). |
| `PDFParser.cpp`, `IndirectObjectsReferenceRegistry.h` | `MAX_XREF_SIZE` is 8,388,608 entries, for object numbers up to 8,388,607, the PDF 1.7 limit on indirect objects, instead of 9,999,999,999: `ExtendXrefToSize()` grows the cross-reference table to the start of a classic subsection or an xref stream `/Index` section, so a section at a huge object number filled the table up to it, which aborted the native process with `std::bad_alloc` or exhausted its memory, and aborted Wasm. `ExtendXrefToSize()` doubles the capacity only up to that limit. `ParsePreviousXrefs()` follows the `/Prev` chain in a loop with one reused table, merging each table before reading the older ones, which `MergeXrefWithMainXref()` lets fill only entries still undefined, so the newest entry still wins. It recursed once per section and held the table of every section, so a chain of about 1000 sections overflowed the Wasm stack, and one of 200000 the native stack. `ParsePreviousXrefs()` fails once the tables of the chain add up to more than 16 times `MAX_XREF_SIZE` entries: a table takes time for every entry up to its highest object number, so one-entry sections at a high object number took about 30 seconds per 1000. The `IndirectObjectsReferenceRegistry` registry is a `std::deque` instead of a `std::vector`, so it grows without holding its old and its doubled copy at once, which aborted Wasm modifying a PDF near the limit. `ReadXrefStreamSegment()` fails once the xref streams of the parser have read more than 16 times `MAX_XREF_SIZE` entries, counted in `mXrefStreamEntriesRead`: an `/Index` may list the same section again and again, which the `/Prev` bound does not count, so one-byte entries of zeros deflated twice took 82.7 seconds in a 7.3 KB PDF. `ParseExistingInDirectStreamObject()` fails an object stream whose header would bring the cached headers, counted in `mObjectStreamsCacheEntries`, past twice `GetXrefSize()` plus 1,048,576 objects: they stay cached for the parser's lifetime and `/N` bounded each one only, so object streams of 33 KB that each list 8,388,600 objects took 128 MiB apiece and four aborted Wasm. Twice, as an incremental update may list objects again in a new object stream while the old one still holds current ones, plus 1,048,576 for files that write a new object stream on every save. A header that fails to parse is cached as `NULL` and fails the objects of its object stream, instead of being parsed again for each of them, which took about 2 seconds per object for an `/N` of 8,388,600 (GHSA-pvfx-h82v-pxjj). |
| `PDFParser.cpp`, `PDFParsingPath.h`, `PDFDocumentHandler.cpp`, `PDFDocumentHandler.h` | `ParseNewObject()` fails while 32 objects are already being parsed, and `ParsePagesIDs()` fails a page tree more than 1024 levels deep, as PDFium does, by the depth of their `PDFParsingPath`, which `GetDepth()` returns. Parsing an object of an object stream parses that stream and its indirect `/Length` first, which can be in another object stream, and so on, and each page tree level is one call deeper, both without a bound, so a chain of about 360 such object streams or a page tree about 850 levels deep overflowed the 64 KiB Wasm stack, and a long chain took time quadratic in its length natively. The Wasm build's stack is 256 KiB, so both limits fit in it. `PDFDocumentHandler::WriteNewObjects()` copies from a work list, to which `CopyInDirectObject()` hands the objects an object references, instead of the two calling each other once per object of a reference chain, so a chain of about 31,000 objects overflowed the native stack and one of about 5,000 the V8 stack on Wasm, whose `RangeError` left the Wasm stack pointer behind for the next call on that instance. The referenced objects go first in the list, so objects are copied and numbered in the same order as before (GHSA-qv8r-jpjv-7hx2). |
| `PDFParser.cpp` | `ParseXrefFromXrefStream()` rejects `/W` widths outside 0..8, and `ReadXrefSegmentValue()` accumulates unsigned, so a wide field no longer overflows a signed 64-bit shift. |
| `TIFFImageHandler.cpp` | `WriteImageData()` and `WriteImageTileData()` free their strip and tile buffers after the loop, so error paths no longer leak them. |
| `OpenTypeFileInput.cpp` | `ReadGlyfForDependencies()` registers a glyph entry for cleanup before parsing it, so a composite glyph naming a missing component no longer leaks it. |
| `FreeTypeFaceWrapper.h`, `FreeTypeFaceWrapper.cpp` | `LoadGlyph()` caches only a glyph that loaded, so a failure is reported every time. `ForgetLoadedGlyph()` invalidates the cache after the native driver loads glyphs into the face directly. `GetStemV()` invalidates the cache too, as the OpenType extender loads "l" into the face directly. |
| `FreeTypeOpenTypeWrapper.cpp`, `FontDescriptorWriter.cpp` | An OS/2 `usWidthClass` outside 1..9 is treated as unknown, and the font descriptor writes `Normal` for an out-of-range stretch instead of indexing past the FontStretch names. |
| `PNGImageHandler.cpp` | `CreateImageXObjectForData()` reads each row through `ReadRow()`, which catches a libpng error with its own `setjmp()` and restores the caller's jump buffer, so a later libpng error (such as a missing `IEND`) no longer jumps into a returned frame, and the image stream is released. | `PDFDocumentHandler.cpp` | `CopyPageContentToTargetPagePassthrough()` fails a page whose `/Contents` is a stream written inline in the page dictionary. Streams must be indirect, but the parser reads them inline too, and the copy cast the entry to a reference and dereferenced null when appending such a page. |
| `StateReader.cpp`, `PDFWriter.cpp`, `ObjectsContext.cpp`, `IndirectObjectsReferenceRegistry.cpp`, `DocumentContext.h`, `DocumentContext.cpp`, `EncryptionHelper.cpp`, `UsedFontsRepository.cpp`, `PDFUsedFont.cpp`, `AbstractWrittenFont.h`, `AbstractWrittenFont.cpp`, `WrittenFontCFF.cpp`, `WrittenFontTrueType.cpp` | Reading a state file for `createWriterToContinue()` fails on a missing or mistyped entry instead of dereferencing null; on an odd-length pair list instead of reading past its end; on a CFF position list over 256 entries instead of writing past `mAssignedPositions`; and on a page tree deeper than 100 levels instead of recursing until the stack overflows. ## Build And Formatting

| File                     | Change                                                                                                                                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `binding.gyp`            | The GYP target builds the v4.9.1 sources with the bundled OpenSSL for PDF 2.0 encryption, defines `PDFHUMMUS_HAVE_GETENTROPY` on Linux and `USE_BUNDLED`, compiles as C++20 on Windows, and uses the `Zlib` directory name. |
| `PDFDocumentHandler.cpp` | Ends with a newline, as every text file in the repository does.                                                                                                                                                             |
| `licenses/`              | License and notice texts of PDFWriter and of the third-party code in it, which the Wasm build assembles into its license notices. Upstream keeps its license at the repository root.                                        |
